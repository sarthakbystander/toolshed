JWT Inspector

Paste a JSON Web Token to read its header and claims, see when it expires, review the security issues it carries, and verify its signature against a secret, a PEM key or a JWKS. Or build and sign a token of your own. Everything runs locally in your tab — tokens and keys never leave the page.

1 · TOKEN

The Bearer prefix and surrounding quotes are stripped automatically. Decoding is read-only and works on any three-part token, valid signature or not.

2 · SECURITY REVIEW
  • Decode a token to see its security review.

This review flags well-known JWT pitfalls (missing expiry, alg: none, algorithm confusion, oversized lifetimes, sensitive-looking claims). It is guidance, not a substitute for validating tokens against your own policy.

6 · VERIFY SIGNATURE

The algorithm is taken from the token header. For HS256/384/512 paste the shared secret (or an oct JWK). For RS*, PS*, ES*, EdDSA paste the public key as PEM or a JWK. The signature is checked against the exact original segments, never a re-serialised copy.

Verify against a JWKS

Paste a JWKS (the JSON with a keys array) as served by your identity provider. Keys whose kid or alg do not match the token are skipped.

8 · SIGNED TOKEN
Signed tokens appear here.

Signing happens in your browser with the Web Crypto API. Nothing is sent anywhere, and the key you type is used only for this operation.

JWT REFERENCE
Structure
base64url(header).base64url(payload).base64url(signature) — three dot-separated segments.
Signing input
Exactly header.payload (the first two segments). Any re-serialisation changes the signature.
exp / nbf / iat
NumericDate values in seconds since the Unix epoch, not milliseconds.
aud
A single string or an array of strings.
alg
Must be pinned by the verifier. Trusting the token's own alg enables algorithm-confusion and none attacks.
Registered claims

The tool labels the standard claims: iss (issuer), sub (subject), aud (audience), exp (expiration), nbf (not before), iat (issued at), jti (id), and OpenID Connect extras such as auth_time, nonce, acr, amr and azp.

Supported algorithms

HS256/384/512 (HMAC), RS256/384/512 (RSA PKCS#1 v1.5), PS256/384/512 (RSA-PSS), ES256/384/512 (ECDSA) and EdDSA (Ed25519). Verification uses the Web Crypto API; ECDSA signatures must be in the raw r‖s form used by JWS.

A note on trust

Decoding proves nothing. A readable payload only means it was Base64url-encoded — anyone can produce one. Always verify the signature, and pin the expected algorithm on the server.
