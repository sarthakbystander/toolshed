How it works

      
Each directive is a list of sources separated by spaces. 'self' means your own origin, 'none' blocks everything, and a bare host such as https://cdn.example.com allows that host. The builder keeps the directives in memory as you edit them and re-renders the policy, the resolved view and the analysis on every change.

      
    
        
  • Build — start from a preset, then add or remove directives and edit their sources.
    • 
        
  • Import — paste an existing header, bare policy or meta tag to decode it into editable directives.
    • 
        
  • Analyse — the policy is scored and checked for weak sources, missing directives and deprecated ones.
    • 
        
  • Export — copy the policy as a header, meta tag, Apache/Nginx/Cloudflare/Netlify config or JSON.
    • 
      


      
Reading the score

      
The score is a heuristic, not a security guarantee. It rewards the directives that reliably block the common attacks: a restrictive default-src, no 'unsafe-inline' or 'unsafe-eval' in script-src, object-src 'none', a set base-uri, frame-ancestors and form-action, and no plaintext http: sources. Use it to spot obvious gaps, then test the policy against your real pages.


      
Fallbacks matter

      
A directive you do not set is not automatically blocked. Fetch directives fall back to default-src, and some fall back further: script-src-elem and script-src-attr to script-src, frame-src to child-src, and worker-src to child-src then script-src. The Resolved directives table shows the effective value and where it came from.


      
Privacy

      
Everything is computed in your browser from the text you type. The tool makes no network requests, uploads nothing, and writes nothing to storage — no localStorage, no cookies, no analytics. Copying uses the browser clipboard API; nothing leaves the page.


      
Limitations

      
    
        
  • The score is a heuristic and cannot know which sources your site legitimately needs.
    • 
        
  • Import decodes the common header, bare-policy and meta-tag forms; HTML entities in a meta tag are decoded, but comments are not stripped.
    • 
        
  • frame-ancestors is ignored in a <meta> tag by browsers — the export still includes it if you set it, so use a real header for clickjacking protection.
    • 
        
  • Nonces and hashes are validated for shape only; the tool cannot check that a nonce matches a real script.
