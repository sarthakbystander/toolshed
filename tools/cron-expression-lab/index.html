Cron Expression Lab

Paste a cron expression to see what it actually means, which fields match what, and exactly when it fires next — in any time zone, with daylight-saving changes taken into account. Or build one field by field. Everything runs locally in your tab.

1 · EXPRESSION

Fields are separated by spaces. Accepted forms include *, 5, 1-5, */10, 9-17/2, 1,3,5, names like JAN or MON-FRI, and macros like @daily.

Macros

@reboot is recognised but has no fixed schedule — it runs once when the machine starts, so no next run times can be computed.

Notes and gotchas

By default, when both day-of-month and day-of-week are restricted, a day matches if either one agrees (the classic cron rule). Use the Day matching selector above to switch to the Quartz-style AND rule, or to ignore one of the two fields.

Next run times are computed from real wall-clock values in the chosen zone, so clocks that shift for daylight saving are handled: a wall time skipped by a spring-forward is not reported, and a time that occurs twice in autumn resolves to a valid instant.

Runs are capped at 50 results and a 20-year horizon; a self-contradictory schedule such as 0 0 31 2 * (31 February) reports no occurrences rather than looping.
